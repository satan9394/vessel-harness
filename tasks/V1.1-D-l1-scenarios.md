### 设计选择（场景 yaml 契约 / mock provider 用法 / 断言原语）

- **对齐不重造**：沿用既有（B016-B023 feature-lane）yaml 形状——`id/type/goal/fixture/task_file/harness/pass/measured/mode`；
  manifest 校验（白名单 key）同步扩展，不引入新契约层。mode 全部 `offline`（确定性 mock lane，跑在隔离 temp 工作区）。
- **mock provider 确定性**：复用 `MockProvider.stream()`（046/049 已实现按脚本产 `message_start → text_delta → tool_call_start/end → usage → message_end`），
  `OFFLINE_SCRIPTS` 里给每场景写确定性脚本；`stream_seen` 断言**不信任 mock 措辞**，改读 runner 订阅 `model_stream_delta`
  总线捕获的 live observation（text/tool），与既有"runner 侧断言不看 mock 自述"纪律一致（BENCHMARK-SPEC §6 / 076）。
- **interrupt 确定性**：interrupt 驱动监听 `model_stream_delta` 到首个 `tool_call_end` chunk 边界时调用 `loop.interrupt()`；
  AgentLoop.consumeStream 每次 chunk 前查 `interruptCtl.aborted`（050），故中断落在 usage/message_end 之间 →
  本轮明确以 `kind=interrupted` 收尾（turn/start→turn/end 配对保持）。event 内同步 interrupt，受 EventBus.emit await 保护，确定性无竞态。
- **steering 确定性**：steering 驱动在首个 `after_tool` 后 `loop.steer('…收窄…STEER-GOLDEN-2026')`；SteeringQueue 在下一 step 边界
  drain 为 `user/message source=steer`（051），mock 下一轮匹配该 marker → 输出改向文案；`steer_seen` 读 session 记录证明注入。
- **resume 确定性**：复用 067 `buildHandoff`+`seedSessionFromHandoff`，把结构化 handoff（§12 字段）作为 `source=handoff` 起始上下文
  注入新 Session，再跑一轮；`resume_seen` 读该记录，续跑 golden 由 mock 输出承接。
- **断言原语**：新增 4 个 runner-side 原语——`stream_seen`（kind/min/pattern，读 streamEvents）、`turn_interrupted`、
  `steer_seen`、`resume_seen`（读 sessionRecords）。这些与既有 `denial_seen/guard_seen` 同一"机制层证据，非 model 自述"哲学。
