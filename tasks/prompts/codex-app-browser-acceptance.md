# Codex 应用任务：Vessel 浏览器运行时验收

> 直接整份粘贴到 Codex 应用中执行。工作目录：`E:\Code_file\Projects\Vessel_Harness`。

你是**审计者**，不是实现者。本次只做观察、点击、截图与记录，**不改任何产品代码/测试/配置**。

## 0. 硬约束

- 只在夹具工作区里新建会话；**绝不删除、不重命名任何已有会话**（侧边栏里可能是用户的真实数据）。
- 不接触真实供应商凭据，不发起真实模型调用；一律用内置 **Mock** 预设。
- 不跑 `npm run test:all`。
- 唯一允许写的文件：`evidence/sessions/2026-10-23-browser-acceptance/` 下的截图，以及
  `evidence/sessions/2026-10-23-browser-acceptance-report.md`。
- 若内置浏览器（IAB）不可用，立刻停止并如实报告 `Browser is not available`，不要用 HTTP/curl 冒充浏览器验收。

## 1. 环境准备

1. 确认端口空闲：`netstat -ano | findstr :5678`。被占用就换 `5679`，并在报告里写明实际端口。
2. 建夹具工作区（系统临时目录，不要用仓库或用户目录）：
   ```powershell
   $ws = Join-Path $env:TEMP ("vessel-audit-" + [guid]::NewGuid().ToString('N').Substring(0,8))
   New-Item -ItemType Directory -Path $ws | Out-Null
   Set-Content -Path (Join-Path $ws 'README.md') -Value '# audit fixture'
   ```
3. 构建前端（服务端只托管 `apps/web/dist`）：
   ```powershell
   npm run -w @vessel/web build
   ```
4. 后台起服务（不要阻塞终端）：
   ```powershell
   npx tsx apps/cli/src/cli.ts serve --port 5678 --workspace $ws
   ```
5. 连通性自检：`curl.exe -I http://127.0.0.1:5678/` 必须是 200 且 `text/html`。
6. 浏览器访问 `http://127.0.0.1:5678`，确认页面加载。

## 2. 准备 Mock 供应商

打开 Provider Hub（供应商/模型设置）：若已有 `Mock（本地测试）` 预设（id `mock`，协议 `mock`，模型 `mock`，无需 key），直接选用；没有就通过「添加/预设」创建它。**不要填任何真实 key。**

## 3. 场景（逐条执行，逐条截图）

### S1 新建会话并跑一轮（BV-01 前置）
在夹具工作区新建会话，发送一句 `hello`，等回复结束。
- 记录：首帧是否可交互、发送按钮状态、回复是否渲染。

### S2 刷新保史（BV-01，卡 254 回归）
按 F5 刷新页面，重新点开该会话。
- 期望：历史完整重现（用户消息 + 助手回复）。
- 反例：空白对话、404、只有一条「加载中」。

### S3 删除端到端（UI-01 / ARCH-02）
再建 **两个** 夹具会话，然后：
1. 删其中一个 → 观察确认态、删除中按钮是否禁用、成功后列表是否立刻移除。
2. 刷新页面 → 期望它不再出现（不能「刷新又回来」）。
3. 对另一个会话的**所在分组**执行组删除，观察是否逐项反馈。
- **只删你自己刚建的**。任何已有会话一律不碰。

### S4 Activity 状态真实性（UI-02 / ARCH-01）
1. 跑一轮正常会话 → 打开 Activity，观察状态从 running 到 completed 的过程是否与真实一致。
2. 跑一轮后立刻点 Stop → 观察该会话在 Activity 里的状态。
- 重点：**被取消/中断的会话不能显示成「已完成」**；若显示为「失败」，记录具体文案与图标。
- 重点：**没有执行证据的项不能显示「已完成」**（引导态、待审批、idle）。

### S5 Stop 的行为（UI-09）
发送一条较长的任务后点 Stop。
- 记录：是否报错、错误出现在哪里（toast/行内/无）、输入框内容是否被保留。

### S6 输入框与工具细节（UI-09）
- 输入多行文本（含换行）→ 记录是否支持换行、Enter 是发送还是换行。
- 触发一次工具调用（若 Mock 不产生工具调用，记录「本次无法触发」而不是猜）。
- 观察工具活动默认是否折叠。

### S7 首屏聚焦与草稿隔离（UI-03）
- 打开应用首屏 → 记录输入框是否自动获得焦点（直接打字能否进入输入框）。
- 在会话 A 输入草稿但不发送 → 切到会话 B → 再切回 A。
- 记录：草稿是否串到 B、A 的草稿是否保留。

### S8 生效 Policy 区域（UI-07）
在设置/Studio/Inspector 中查找是否存在**只读**的「当前生效的 Policy」展示（不是可编辑表单）。
- 有 → 截图 + 说明展示了哪些字段。
- 无 → 结论写「不存在」，并记录你找过的位置。

### S9 响应式 / 主题 / 语言 / 缩放矩阵（UI-10）
组合矩阵，每格一张截图：

- 宽度：360 / 768 / 1024 / 1440 / 1920
- 主题：浅色 / 深色（各覆盖一遍关键页面：会话、Activity、设置、供应商）
- 语言：中文 / 英文（抽查导航、按钮、空状态文案）
- 缩放：100% 与 150%（抽查 1440 宽下的会话页）

每格记录：是否出现横向滚动条、文字被截断、元素重叠、按钮点不到。

## 5. 收尾

1. 停止服务，确认 `netstat` 里该端口已释放。
2. 报告里写明：夹具工作区路径、是否保留（默认保留，便于复核）、实际端口。
3. 明确声明哪些结论来自浏览器实测、哪些仍无法验证。

## 6. 判定纪律

- 没有截图或 DOM 观测的，不算结论。
- 发现缺陷**只记录不修**，给出「最小复现步骤 + 期望 vs 实际」。
- 任何一条做不到（例如 Mock 供应商无法创建、IAB 不可用），直接写「无法验证 + 原因」，不要编造通过。
