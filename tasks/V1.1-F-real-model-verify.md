### 凭据转接方式（CC Switch 路径探查结果 + 落库方式，**无明文密钥**）

- **CC Switch 配置实测**：主体不是旧文案猜测的 `~/.cc-switch/config.json`，而是 **SQLite 库
  `C:\Users\USER\.cc-switch\cc-switch.db`**（35MB），表 `providers`（`app_type='opencode'`，
  name="OpenCode Go"，实测两条 id=`hs`/`zl`），`settings_config` 为 AI SDK openai-compatible 形状：
  `options.baseURL=https://opencode.ai/zen/go/v1`，`options.apiKey` 采用 opencode 的
  **`{file:<path>}` 文件引用**语法（`{file:~/.config/opencode/secrets/hs-api-key}` 与
  `{file:.../zl-api-key}`），非内联明文。真实 key 文件在 `~/.config/opencode/secrets/{hs,zl}-api-key`
  （各 67 字节 `sk-...`，两个 key 不同）。
- **转接落库**：`migrateOpencodeGoCredential` 探查 DB → 解析 `{file:}` → 进程内读 key →
  `CredentialStore.set('vessel','opencode-go', key)`（034/069 Windows DPAPI 加密）。
  `~/.vessel/secrets.json` 实测 `backend=windows-dpapi`，新增第 3 项
  `service=vessel account=opencode-go`（cipher 392 字符，**全文件无明文 `sk-`**）。
- **resolver 读取**：`credentialAwareOpencodeGoKey` 先 `getSync('vessel','opencode-go')`（DPAPI 解密，
  进程内），再 env 回退；无值 → undefined → lane/gate 降级 pending。全程只读 store、不写盘。
- **密钥安全确认**：key 只在进程内出现 + DPAPI 密文落库；`V1.1-F-verify.json` /
  `V1.1-F-openmodel-lane.json` / lane 报告 / release-report / 本文档**均不含任何密钥片段**（已核）。

### 设计选择与踩坑

1. **CC Switch 配置探查结论**：任务卡预想的 `~/.cc-switch/config.json` / `claudeProviderPresets.ts`
   不适用于本机——实际是 SQLite `cc-switch.db` + `{file:}` key 引用。探查路径如实记录，未臆断。
2. **CredentialStore 用同步 getSync**：`OpencodeGoKeyResolver` 是同步签名，而 CredentialStore.get
   是异步 → resolver 统一走 `getSync`（CredentialBackend 同时提供 sync/async），避免 async 泄漏。
3. **node:sqlite 是实验 API**：静态 `import { DatabaseSync } from 'node:sqlite'` 会让 vite/vitest
   解析失败（builtin id 无法外部化）→ 改为方法内 `await import('node:sqlite')` 惰性加载；测试注入
   fake reader 不触发。
4. **gate 修复（gates 补齐核心）**：084 原 real-model-bench 判 `degraded = some(!available) ||
   injectedProvider===undefined`——经 `providerResolver` 正常供 key 也会被误判 degraded 而永远
   pending。改为 `anyAvailable = some(available)`，无任何模型可解析才 pending；部分/全体解析到则跑
   lane（lane 内部对不可解析模型逐行 pending-environment）。实测修复后 gate 4 真正跑起了 MIMO lane。
5. **billing 阻塞 ≠ 模型回归**：lane 13 行 failed 全部是 `401 CreditsError Insufficient balance`。
   新增 `judgeRealModelLaneWithBilling` 识别该模式 → 显式 pending + note（不伪造 pass、不误判 fail）。
6. **真实跑发现余额不足**：账户鉴权有效、/v1/models 连通、请求到达后端，但 opencode-go 账户余额不足
   致聊天 401。按密钥铁律与 084 语义如实 pending + 记录原因，未反复重试。
