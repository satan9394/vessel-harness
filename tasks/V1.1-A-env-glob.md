## 问题

`packages/policy/src/risk/globmatch.ts` 的 glob 编译：`**/` 被编译为 `.*/`（必含一层目录），
因此 pattern `**/.env`（及 `**/secret` 类）**不匹配根级 `.env`**（根目录文件，前面没有目录前缀）。
075 的 S007 判据因此把凭据放 `creds/.env` 才能命中 deny——**根级 .env 是逃逸点**（真实安全缺口：
工作区根目录的 `.env` 可被 Read 工具读取而 deny_read / read-secrets 不拦截）。

根因（globmatch.ts L6-51）：`**` 分支仅处理"`**` 前是 `/`"时的 `(?:/.*)?`，未处理"`**` 紧跟 `/`"
（pattern 开头 `**/foo` 或 `dir/**/foo`）——此时 `**/` 应匹配**零层或更多**（即 `foo` 也应命中）。

## 方法

- 修 `**` 分支：当 `**` 后紧跟 `/` 时，`**/` 编译为 `(?:[^/\\]*/)*`（零个或多个目录段）或等价零层可选——
  保证 `foo` 也在 `**/foo` 范围内；保持 Windows `\` 归一。
- 全量回归确保既有 pattern 语义不倒退（尤其 `**` 全递归、`dir/**` 含自身——现 L16-18 已处理 `/` 前 `**`；
  补 `**/` 开头场景）。

### 修复设计（globmatch.ts `**/` 编译写法）

原 `**` 分支无条件编译为 `.*`（`**/` 因此得到 `.*/`，必含一层目录，根级 `.env` 逃逸）。
改为：当 `**` 后紧跟 `/`（`pattern[i+2]==='/'`）时，`**/` 编译为 `(?:[^/\\]*/)*`（零个或多个以 `/` 结尾的目录段），
消费 `**` 与随后的 `/`（i+=3）。`/` 前 `**` 的既有分支（L16-18 原逻辑：`re.endsWith('/.*')` → `(?:/.*)?`）原样保留，
因此 `dir/**` 含 `dir` 自身、`a/**/b` 含 `a/b` 语义不倒退。Windows `\` 归一在 `globMatch` 入口（value 与 pattern 均 `\`→`/`），
`[^/\\]` 段字符类同时排除 `/` 与 `\`，行为一致。

- 改动文件：`packages/policy/src/risk/globmatch.ts`（仅 `**` 分支，+4 行注释、+1 逻辑分支）。
- 新增测试文件：`packages/policy/src/risk/globmatch.test.ts`（14 用例）。
- 改动测试：`packages/policy/src/policy.test.ts`（追加 V1.1-A describe：deny_read `**/.env` 拦根级 `.env`）。

diff 摘要（globmatch.ts 核心）：
```diff
       if (pattern[i + 1] === '*') {
-        re += '.*';
-        i += 2;
-        if (re.endsWith('/.*')) {
-          re = re.slice(0, -3) + '(?:/.*)?';
+        if (pattern[i + 2] === '/') {
+          // `**/` = zero or more directory segments ...
+          re += '(?:[^/\\\\]*/)*';
+          i += 3; // consume `**` and the following `/`
+        } else {
+          re += '.*';
+          i += 2;
+          if (re.endsWith('/.*')) {
+            re = re.slice(0, -3) + '(?:/.*)?';
+          }
         }
         continue;
       }
```

### 踩坑

1. `RegExp.prototype.source` 会把 `/` 转义为 `\/`，故编译形断言写成 `^(?:[^/\\]*\/)*\.env$`，与手写字面量 `/` 不同——测试第一版因此误红一次，已校正。
2. `PolicyEngine.decide` 中 `Read` 未传 `requiredPermission` 会按 `danger-full-access`（未注册→danger，D6）在 ⑥ profile compare 阶段 fail-closed 拒绝；断言"非 .env 放行"必须显式传 `{ requiredPermission: 'read' }`，否则与 glob 修复无关地误红。同意却需要 read spec。
