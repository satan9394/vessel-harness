### 消费方 / 完整性核查（摸清现状结论）

- `apps/local-server/src/goalSeam.ts:295-296`：唯一生产消费点，**只读 `generator/evaluator.lastRun`**（最近一条）
  → 有界环恒满足。IterationStore `appendIteration` 以 `entry.generator/evaluator` **整记录即时入参**
  （persist 时取 lastRun 快照），**不扫描 adapter 全量 history** → 有界不丢任何迭代（soak countConsistent=true 佐证）。
- `runs`（全量）仅测试/审计读取；默认上限 100 不影响既有断言（既有 runs 用量 ≤2）。
- retention 语义：adapter 内存内只保最近 historyLimit 条；旧条目 FIFO 覆盖（不可回首），计数走 totalRuns；
  持久迭代记录（store）不受影响。

### 068 soak 重跑（bounded history 生效，各 adapter 超 100 次仍见顶）

| run | attempts | iterations | heapStart→end | 说明 |
|---|---|---|---|---|
| 120t/30r（全 met） | 360 | 240 | 13.6→13.3（-0.3MB） | flat；residue=0；countConsistent=true |
| 40t/30r/maxAcc14（含 handoff/pause） | 537 | 289 | 13.7→15.0（+1.3MB） | handoffs=16 chain=1 resume=true；countConsistent=true |
| 60t/40r/maxAcc20（长跑 GC 沉降） | 1201 | 631 | 11.8→14.1（见 plateau） | round10 冲 20.3 → round15 15.7 → round20 **13.5** → end 14.1（GC 回收被覆盖 ring 记录，**非单调上升**）；resume=true |

对比：**soak 前** 1801 attempts heap 13.5→24.3MB **单调上升**（无界 history 全量保留 → GC 永不回收）。
**现在** 1201 attempts heap 见顶后回落并保持 ~13-14MB（有界 ring 覆盖 → 旧记录可 GC）。
`countConsistent=true`、`roundTripQueueReadable=true`、iterations-per-task 可全量回放 —— **迭代完整性零损失**。

### 设计选择与踩坑

- **有界环语义**：选 RingBuffer（保最近 N + total 计数）而非仅计数裁剪，因消费方 goalSeam 需 lastRun 快照、
  审计需 recent context；total 保证计数型消费方不因覆盖失真。默认 100 ~ 600KB 上界，平衡可回首窗口与内存。
- **队列索引**：内存索引为主会 stale（跨实例状态改）。用 **mtime 校验刷新**：每 list 一次 readdir + 对每个
  已知 id stat meta.mtime，变了才重读（内容读降为 O(changed)），未变只 stat —— 正确性以 disk 为锚，磁盘 IO
  从 JSON parse 退化为 stat。claimNext 首次装载后走 pending 游标（O(1) 候选）+ 单条 disk re-read 校验（保跨
  实例不重复领取的既有语义）。
- **踩坑**：① 有界环取快照要处理 JS 负模（positiveMod 包装）；② 一版实现里 `list` 增量 sync 只合并新目录而
  不刷新既有状态 → 跨实例状态变更不可见（自测捕获）→ 改为 mtime 校验全量刷新；③ 内存索引在「单写者 + fresh
  实例读」模型下正确（文档既有约定：多写者需自行串行）；④ claimNext 热路径刻意不 readdir（只见本实例写透传 +
  fresh 实例全装载），故整池 drain 为 O(N)。
- **迭代完整性**：IterationStore append 在 persist 时以 lastRun 整记录入参，与 adapter 内存有界无关 ——
  任意 attempt 数下迭代均可回放。
