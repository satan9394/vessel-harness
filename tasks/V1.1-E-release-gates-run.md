### 改动文件与 diff 概览

1. **`benchmarks/runners/src/run-release-gates.ts`（新增，驱动脚本）**：按 docs/RELEASE-GATES.md 库
   API 装配 8 gate → 顺序实跑 → 写 report 到 `benchmarks/reports/`。两处关键决策：
   - **Windows spawn 修复**：084 默认 `gateDefaultRunCommand` 用 `execFile{shell:false}` 直调
     `npx`/`npm`，Windows 上它们是 `.cmd` shim，无 shell 时 spawn 直接 ENOENT → Build/Unit/Packaging
     gate 永远拿不到真实命令输出。驱动注入自定义 `RunCommand`（`shell:true`）修复，不动 084 框架源码。
   - **deterministic-bench 扩集**：按 V1.1-E 任务要求，把 L1 可跑集从 084 默认 B001-B005 扩到
     **B001-B005 + B016-B027（17 个，含 V1.1-D B024-B027 streaming/interrupt/steering/resume）**，
     复用 076 `runScenario` + 084 `judgeScenarioRuns`。
   - 报告注解：为 unit/deterministic-bench 注入环境/范围 note（不改变 verdict，保证 .md/.json 一致）。
2. **`benchmarks/runners/src/release-gates/gates.ts`（1 处修复）**：resume gate 调用 `runSoak` 时
   显式补 `pauseEveryRounds: 1`。V1.1-E 实跑发现：默认 `pauseEveryRounds=7` 而 gate 用 `totalRounds: 3`，
   round(1..3) 永不为 7 的倍数 → 暂停/续跑 flap 从不触发 → `pauseResumeCycles` 恒 0 →
   `judgeSoakResume` 的 `pauseResumeCycles>=1` 恒 fail → **该 gate 永远红**。显式降到 1 让每次 round
   边界都 flap，真正行使 066 暂停/续跑，判据如实判定（实跑后 pauseResumeCycles=2，pass）。
3. **`docs/V1.1-ROADMAP.md`**：§5 V1.1-E 状态从「待 C 之后」更新为「已实跑出 release-report」。
4. **`tasks/V1.1-E-release-gates-run.md`**：本卡（验收勾选 + 状态；本工作证明）。

### 实跑发现与处理

1. **084 `gateDefaultRunCommand` 在 Windows 下 spawn `npx`/`npm` ENOENT**（`.cmd` shim，无 shell）。
   → 驱动注入 `shell:true` 的 RunCommand，真实命令在非受限 Windows 可跑（框架本就留 RunCommand 注入缝）。
2. **resume gate 配置缺陷**：`totalRounds:3` + 默认 `pauseEveryRounds:7` ⇒ 永不暂停/续跑 ⇒ 恒 fail。
   → `gates.ts` 补 `pauseEveryRounds:1`，判据如实转 pass。
3. **Unit gate 触发既有 process-tree 计时 flaky**（非本卡回归）：整机高负载并行下 30s 超时。
   → 如实 fail + 报告 note 标注；隔离 11/11 重新证实；不伪造 pass。留给指挥按惯例判 partial。
4. **Packaging gate pending（根 .gitignore/dist 无 root dist）**：monorepo 为 solution tsconfig 逐包
   产出 dist，根目录本就不产出 `dist/`。084 语义 pending，如实记录。
