## Cognitive memory review

`HybridMemoryStore` extends the existing SQLite session projection, reusing `records` and `messages_fts`; no additional SQLite loader or package dependency was added. FTS5 BM25 and pure TypeScript cosine ranks fuse per message through RRF, then apply the requested limit/minimum score. Offline producers provide optional embeddings through the registry API; no embedding model or external agent is called. Missing, zero-norm and dimension-mismatched vectors leave keyword recall available. Finite-vector validation rejects sparse arrays and limits dimensions; scaled cosine avoids numeric overflow/underflow.

Embedding facts are appended to a companion JSONL journal with content fingerprints, so cache restart/rebuild/corruption preserves matching vectors and message replacement invalidates stale vectors. Reflective facts are deterministic templates derived from policy denials and self-healing/error-code records, keyed by session/sequence provenance. Manual rule reinforcement has its own append-only JSONL journal. These companion journals are authoritative producer facts; only SQLite is disposable. Reconciliation and rebuild recover event frequencies without duplicate reinforcement. Existing corruption quarantine preserves files by rename.

The application registry exposes hybrid retrieval and offline embedding ingestion. Composition lazily rebuilds workspace-scoped cognitive memory from historical JSONL; the builder matches the current actual user/steer goal, chooses up to five rules and bounds guidance tokens. JSON-encoded lessons remain explicitly untrusted user-level memory, outside the stable system/policy layer. Raw denial reasons and stderr never become recommended instructions. Long goals retain full model-visible content while recall is bounded; optional projection failures preserve ordinary chat and authoritative history.

Independent read-only review accepted the final memory implementation after correcting embedding durability/stale association, sparse vectors, exhausted retry-code extraction, projection work per event, long-goal recall failure and optional-store lifecycle. The worker's logged warm median is **9.952 ms** (`stage181-worker-targeted.log`); the independent concurrent run measured **12.344 ms**. Both used 1,000 local messages/four-dimensional vectors and passed the unchanged <15 ms assertion. This measures warm retrieval, not cold startup, arbitrary corpus size or arbitrary embedding dimensions.
