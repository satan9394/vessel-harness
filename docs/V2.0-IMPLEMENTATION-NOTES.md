## Delivered behavior

- `vessel mesh` (`swarm`): status, peers, authenticated heartbeat RTT. Daemon composes the existing mesh and provisions optional peers from its root/mesh-peers.json. Responses omit peer secrets.
- `vessel memory` (`mem`): filtered rules, RRF search, rule/category frequency and embedding statistics. Uses the workspace .harness/cache/session_index.db shared with composition.
- `vessel doctor` (`diagnose`): Node >=20, npm lockfile uniqueness, read-only SQLite integrity/WAL/permission checks, native sandbox availability, configured credentials, and authenticated daemon residency. Statuses and repair suggestions; network probing is opt-in.
- `AutonomousReflectionEngine`: deterministic policy/tool/evaluator templates, normalized-trigger merging, durable provenance, frequency/timestamp/confidence evolution, severity filtering and optional dry extraction.
- Composition collects failure/recovery and evaluator events outside the reply event path, flushes on close, and recalls persisted lessons through the existing bounded context builder. Raw error/remedy instructions do not become recommendations.

## Operating boundaries

- Doctor defaults to offline local credential availability; endpoint authentication requires --probe-network. Tests use offline mocks and local fixtures.
- CLI search uses lexical RRF for sessions/rules; store callers can supply embeddings for vector fusion. CLI does not generate query embeddings.
- Recovery pairing deliberately uses the next same-tool result within the same turn. Confidence records observation strength, not proof that arbitrary retries are safe.
- Existing journals remain authoritative; old rule IDs migrate and identical provenance does not increase frequency or rewrite the journal.
- SQLite requires Node with node:sqlite support; doctor reports a database failure on unsupported runtimes while its Node minimum check remains >=20.
- No packages/core edits, real external Agent launches, new external dependencies, alternate lockfiles, permission changes, commits, or pushes. Test cleanup uses only test-created os.tmpdir fixtures.
