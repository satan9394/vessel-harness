# V1.6 规划：工业级团队协同工作台、常驻守护进程与高性能会话中枢 (V1.6-ROADMAP.md)

> 依据：V1.5（Epic 174）已圆满交付自适应上下文防爆、MCP 内核 Job Object 绑定、Staged DAG 编排与流式持久化；  
> 本规划旨在将底层分布式团队能力全面升维至人机交互界面与常驻生产环境，攻克终端关闭任务中断、无图盲操 DAG、工具执行瞬态抖动崩溃、以及海量历史会话检索缓慢等关键瓶颈。  
> 状态：本地全门禁与独立审查通过，待用户验收（任务卡 175–179）；交证入口：`V1.6-IMPLEMENTATION-NOTES.md`。

## 0. 核心定位与技术愿景

随着 Vessel 具备了成熟的底层 DAG 调度和子代理网格能力，系统需要从“后端运行时完善”跨越到“工业级长效交付工作台”：
1. **交互可视化与人在循环审批（Visual DAG Canvas）**：
   - 将 Epic 172 的 DAG 状态机与方案预审（Approve & Run）以交互式可视化画布透出，支持在任务启动前直观调整各节点角色指派、模型快照与参数，并在执行中可视化监控任务流转与产物交付。
2. **后台无头常驻与进程拓扑解耦（Headless Daemon & Tray）**：
   - 彻底摆脱必须保持终端窗口前台打开的局限，提供守护进程常驻模式与系统托盘驻留，配合高熵 Launch Token 保证本地安全环回通信，任务完成或需人工干预时主动触发桌面通知。
3. **工具执行层自愈与输出流控（Tool Self-Healing & Bounded Output）**：
   - 解决 Windows 文件锁（EBUSY）与瞬态网络波动导致的过早退出；对工具产生的海量日志进行行级与字节级安全截断与摘要化，保护 V8 堆内存与模型上下文。
4. **高性能 SQLite WAL 会话索引与全文检索（High-Performance Session Index）**：
   - 在保持 JSONL / 分块流式为单一可信事实源的前提下，引入只读加速的 SQLite WAL 会话元数据中枢与 FTS5 全文检索引擎，实现跨会话微秒级检索与知识图谱记忆检索。

## 2. 架构红线与禁做铁律 (绝对遵循)

1. **薄核（Thin Core）铁律**：`packages/core` 保持极致简洁，SQLite 索引与桌面守护进程完全作为外部加速与宿主接入层，核心状态机与 Session 契约保持零污染。
2. **严禁调用真机 Agent**：严格遵守 `AGENTS.md` 禁做清单与任务 153 纪律，所有单元测试与回归套件必须使用内存 Mock 桩与离线仿真，严禁拉起本机真实安装的 `claude`/`codex`/`dsh`/`opencode` 进程。
3. **包管理器铁律**：严格遵守决策点 19，绝对禁止引入 `pnpm`/`bun`/`yarn` 锁文件，保持 `npm ci` 跨平台纯净可用。
4. **删除铁律**：非测试自建且位于 `os.tmpdir()` 之下的临时目录，一律走回收站，严禁任何硬删命令。
5. **Clean-room 规范**：遵循 Vessel 既有的 Behavior IR 与事件契约设计，严禁复制代码侵权。
