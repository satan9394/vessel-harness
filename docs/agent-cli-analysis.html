② 它对应哪些 Agent 的哲学（分层合成定位）

依据 HARNESS-ANATOMY 七种范式分类 + D3 各决策点"组合取各家可迁移点"。没有哪一层是单家原样照搬——每层都是"某家骨架 + 另一家纪律"的合成。

内核 / Loop
DSH 事件溯源薄核哲学（模型可见 ⟺ 已记录、崩溃=重放）+ Claude Code 终止语义哲学（纯文本即停）+ Claw 健康探针。拒：Pi 双轨 loop / Claw 循环拆到 CLI / Codex 2881 行单文件。
上下文
Hermes 缓存纪律哲学（三层拼接、每会话一次、prefix cache 神圣）+ DSH 注入即数据哲学 + Claude 按需加载与 user-message 指令哲学。拒：Claw 全量重发 / Pi 每轮重放。
工具
Pi 极简内核工具哲学（最小集 + 定义/执行解耦）+ DSH 统一流水线与并行原语哲学（guard 单调、独占屏障）+ OpenCode 健壮性哲学（INVALID_ARGS 自修复）。拒：Claw 万行 tools、Claude 40+ 工具面。
策略 / 安全
Claude Code 行为分层哲学（软硬分离、deny→ask→allow、protected 铁律）+ DSH fail-closed 哲学（guard 单调、审计对、never 强制）+ Codex 工程语义哲学（三档命名 + 沙箱边界模型）。拒：Pi 以用户权限跑 / OpenCode 无 OS 沙箱。
验证 / 多智能体
Claude 验证外部化哲学（干活模型不自证）+ Codex 受限评审哲学 + DSH 机制非角色哲学（Evaluator 不是新原语）+ Claw mock-parity 方法论哲学。
会话 / 记忆
DSH 事件日志哲学（会话=发生过什么）+ Hermes 文件式记忆哲学（冻结快照、写盘不改当前提示、只归档不删除）。
产品 UX
opencode 第三方优先哲学（/connect+/models 解耦、TUI 无参进入）+ cc-switch 向导完整性哲学（预设填充、Fetch Models、错误降级）+ Claude /model 双语义 + Codex 三档命名；@clack 轻量（吸收 opencode 弃 React-ink 的教训）。
总纲（差异点）
Behavior IR 保存"该怎么行为"而非"某家 prompt 写了什么"——没有任何一家的现成哲学。CL4R1T4S 证明行为可归纳（跨产品一致性极高）是前提；anat:0.3-5："没有哪家把行为做成显式 IR"。这是与 7 家 harness 的根本差异。

3.6 与 Claude Code / Codex"整段人设"的本质差异

cc / codex / claw / pi

行为 = 手写整段人设长 prompt（身份→语气→工具纪律→护栏…），文本与运行时无编译契约，行为散落 system 段落/指令/hook/权限/compaction 五处。

Vessel（原 cah）

system 只含"一句身份 + 编译产物"。行为是 behavior.default.yaml 里可版本化、可校验、带 channel/conformance 的声明式 IR，经 Behavior Compiler 编译而来。同一条 IR 将来对 Claude/GPT/DeepSeek 渲染不同措辞，但 IR 只有一个。

四条分界：① 保存"该怎么行为"而非"某家 prompt 写了什么"；② 软硬分离——"不要删 .git"同时是 prompt 文字 + Policy Engine 硬执法（禁止只写 prompt）；③ 每条 IR 带 conformance 供 Evaluator/Conformance Suite 机器断言；④ CL4R1T4S 等 UNTRUSTED 语料只能经 Raw Prompt→Parser→Behavior Extraction→Review→IR 进入，禁止原文直进 system。
