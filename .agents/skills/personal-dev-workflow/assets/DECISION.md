# 决策卡（DECISION）

> 用途：在写任何契约之前，把「做什么、不做什么、怎么算做完」定在一页里。它是给人看和给人签的；写完后按右列映射成 PDW 契约，再由 `pdw check` 校验。
> 不建模板树、不设阶段、不引入评审角色。一页写完即可冻结。

## 1. 问题

要解决的具体问题是什么（一句话，可观察）。不是方案，也不是功能名。

## 2. 目标形态

做完之后，用户能做什么之前做不到的事。不写实现、不写技术栈、不写目录结构。

## 3. 范围边界

明确不做什么。写出至少一条「这次不做」，以及做了也不算完成的邻近事项。

## 4. 验收草案

3–5 条可执行判据，每条写清：命令（可执行 + 参数）、期望退出码、失败时看什么。行为是否正确、界面是否好看这类不可机械判断的项，写明「由谁在什么时点人工确认」。

## 5. 预算与停止条件

调用次数上限、墙钟上限、修复次数上限；达到上限时是停、降级还是请示，写给谁。

## 6. 留给运行时的假设

谁派活、几个并发、在哪个宿主（本机 CLI / Multica squad）、失败后由谁接手。写错这一栏不会让契约失效，但会让分派方式出错。

---

## 映射到契约字段

| 本卡 | 契约字段 | 说明 |
| --- | --- | --- |
| 1 问题 + 2 目标形态 | `goal` | 两段合并成一句可判定的话；不要带方案 |
| 3 范围边界 | `scope` | 只写允许改的路径；「不做」写在契约外的本卡里 |
| 4 验收草案 | `acceptance` + `checks` | 每条验收一个 `{id, description}`；能机器判的落成 `checks[{id, command, args}]` |
| 5 预算 | `limits`（项目配置） | 契约本身不写预算，预算在 `.pdw/config.json`；本卡只定本次要多少 |
| 6 假设 | 无 | 运行时信息；若宿主是 Multica，`run` 会被拒绝，只能走 squad |

## 示例（骨架，不含真实路径）

```
1 问题：设置页保存后刷新会丢值。
2 目标形态：保存后刷新仍显示用户改过的值。
3 范围边界：只改 src/settings 与 tests/settings.test.mjs；不改接口协议；迁移旧数据不算完成。
4 验收：node --test tests/settings.test.mjs 退出码 0；手动刷新一次确认值仍在（由提议者本人确认）。
5 预算：CLI ≤ 6 次，墙钟 ≤ 20 分钟，修复 ≤ 1 次；超限停下并报告。
6 假设：本机 CLI 接力，单实现者，复核另起会话。
```
