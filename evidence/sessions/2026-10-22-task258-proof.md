# Task 258 — Activity completion truth

Local implementation verified on `main`; no commit/push. Scope: [task 258](../../tasks/258-false-completion-signal.md).

## Change and boundary

Product source changes are confined to `activityRoutes.ts` and its tests. A finished team requires a nonempty task list with every task completed. Failures take precedence over cancellations, which take precedence over success. Missing/unknown evidence stays unknown. Team/subagent projections now include outcome/statusSource.

No `server.ts` edit: it already examines the latest start/end record. Existing HTTP tests for a newer unfinished turn after an older success, missing terminal evidence, and successful turns passed. Task 254 pending-goal behavior and task 255 truncation handling remain unchanged and their tests passed.

No UI edit: `ActivityQueue.tsx` uses `activityStatusLabelKey(run.status)`; the existing bilingual labels are `未确认` / `Unknown` and `失败` / `Failed`. Cancellation retains the existing failure display while the API preserves `outcome: cancelled`. Separate cancellation/interruption badges and browser acceptance are not claimed by this card.
