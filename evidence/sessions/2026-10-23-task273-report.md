## Cache and provenance contract

- `packages/context/src/compaction/Compaction.ts:93-124` expands overlapping prior ranges and reads raw source events, excluding compaction/start/end. It avoids recursively serializing projected historical-summary metadata as original source evidence. Tool-pair previews retain IDs and immutable source references rather than repeatedly copying bulky payloads. The authoritative log is retained.
- `Compaction.ts:152-153,176-177` keeps `metadata.provenance` and `summaryHash` on the committed summary. `packages/shared/src/projection.ts:102-104` keeps that metadata on the projected summary message. No provenance removal or schema change was used to obtain the performance result.
- `projection.ts:77-79` recalculates the summary/provenance digest on every projection. It does not cache approval of mutable summary metadata.
- `projection.ts:80-89` serializes current non-compaction source records on every call. A WeakMap associates each record object with its current persisted JSON snapshot. Changed JSON creates a new snapshot, including nested mutations; object identity alone cannot establish integrity.
- `projection.ts:90-96` selects the inclusive provenance seq interval. Its per-commit WeakMap reuses canonical SHA-256 only when the ordered snapshot identities and count match. Source replacement, removal, reorder, seq changes or content changes invalidate/reselect evidence. It still compares the current expected sourceHash with the independently derived digest every time.
- Independent recomputation remains `canonicalArgumentsHash(JSON.parse(JSON.stringify(rawEventsInInclusiveRangeWithoutCompactionEvents)))`. The producer and reader agree on this JSON persistence representation. Canonicalization is cached, not current-byte inspection. This reduces repeated canonical parsing/sorting/hashing across historical commits; it does not claim constant-time replay or eliminate all per-call serialization.
